### 关键结论（重要，别再踩）
- **真磨砂必须分层**：`backdrop-filter` 元素的子元素无法糊到该元素之外的内容（会形成 backdrop root）。
  所以不能把 `backdrop-filter` 放在 `.capsule` 上再让 `.event-item` 也加 `backdrop-filter`。
  现在的结构：`#bg`（底图） → `#glass > #frost`（面板磨砂） → `#edge`（描边） → `.capsule`（内容，无 filter/opacity）。
  这样卡片自己的 `backdrop-filter` 才能糊到背景图，卡片才真的像玻璃。
- 窗口是 `transparent: true` 时 CSS 糊不到桌面，只能靠 `setBackgroundMaterial('acrylic')`；
  该模式用环境变量 `TT_CALENDAR_ACRYLIC=1` 开启，并注入 `ACRYLIC_OVERRIDE_CSS`
  （现在会隐藏 `#bg`/`#glass`、压平方角，因为 DWM 已经把整窗铺满并吃掉圆角）。
- 主题令牌挂在 `body.theme-dark/light`（不是 `.capsule` 上），否则 `#bg`/`#frost` 读不到变量。
- 空白处拖动：`html, body` 与 `.content` 都设了 `-webkit-app-region: drag`，交互控件单独 `no-drag`。
- 快捷键冲突：`set-hotkey` 必须做**整体回滚**（新键注册失败 or 抢了别的动作的键都要回滚），
  否则会把别的动作的注册悄悄顶掉。`reset-hotkeys` 通道用于恢复默认。

### 事故：所有按钮点不了（当天修复）
- 原因：`-webkit-app-region: drag` 的拖拽区会**吞掉鼠标事件**。重写时把 `drag` 放到 `body` + 整块 `.capsule`，
  但只在父容器 `.acts` / `.body` 上写了 `no-drag`，按钮自身没有 —— 结果整窗都成了拖拽区，点击全部失效。
  设置窗口还叠加了 `.container` 继承 drag + `.body` 是滚动容器，问题更顽固。
- 修复原则（以后一律照做）：
  1. `html, body` 设 `no-drag`，拖拽区只放具体层（面板 `.capsule`；设置窗只放 `.hdr`）。
  2. 顶部统一写 `button, input, select, textarea, a, [role="switch"] { -webkit-app-region: no-drag !important; pointer-events: auto; }`。
  3. 全屏装饰层（`#bg/#glass/#frost/#edge`）显式 `no-drag` + `pointer-events: none`。
  4. 页面脚本里 `ipcRenderer` 一律用带兜底的 `const ipc = window.ipcRenderer || {on,send,invoke 空壳}`，
     否则 preload 一旦没注入，脚本会在绑定中途抛错 → 后面所有按钮都收不到监听。

### 真正的元凶：preload 在沙箱里 require('path')（已修）
- 设置页弹「界面通信未就绪」= `window.ipcRenderer` undefined = preload 根本没执行。
- 原因：`manage-preload.js` 里写了 `const path = require('path')`。**Electron 20+ 渲染进程 preload 默认
  `sandbox: true`，沙箱里只能 require `electron / events / timers / url`**，`path` 会直接抛错，
  整个 preload 注入失败且不打印任何东西。
- 修复：`manage-preload.js` 去掉了 `require('path')`，自己用字符串实现 `basename`；
  并在两个窗口加了 `webContents.on('preload-error', ...)` 把失败原因打到控制台。
- 教训：preload 里**永远不要 require Node 内置模块**（除非显式 `sandbox: false`）。
  想给页面提供工具函数，就在 preload 里手写或走 IPC。

- **磨砂强度** `config.frost = { bg, card }`（0-100）：`bg` 默认 0（直接显示背景图），`card` 默认 55。
  换算：bg → `blur(0~40px)`，card → `blur(0~30px)`；为 0 时给 body 加 `no-frost-bg/card` class

- **两个窗口共用同一套背景**：`#bg`（同一张 dataURL）+ `#glass>#frost` + `#edge`，

- **启动闪两次的三个成因（都已修）**：
  1. 窗口创建即显示 → 先出空白帧/白底。改为 `show: false`，页面首屏（主题/背景/磨砂/缓存日程）

  2. `visibilitychange` 时把 `.capsule` 透明度压到 0.75，再显示时弹回 1 → 每次 F10 都闪一下。已删除。
  3. 隐藏时渲染进程被节流，再唤起要重新合成。设 `backgroundThrottling: false`。
- **面板精简**：去掉标题、副信息行（更新于/共 N 项）、底部「还有 N 项」；

  日程条内部文字（标题/时间/地点/日历名）保留 —— 那是面板的信息主体。
- 设置窗口不再 `parent: capsuleWindow`（parent 隐藏时子窗口在 Windows 上会跟着不可见，

### 第三轮：F10 闪烁真因 / 卡片真磨砂 / 智能隐藏
- **F10 闪烁的真因不在窗口，在渲染层**：窗口 hide 期间内容高度被算成 0，
  ResizeObserver 触发重排 → 只渲染 1 条；show 时又重排回 N 条，一来一回就是"闪"。
  修法：`canLayout()`（`!document.hidden && clientHeight>24`）挡住无效尺寸 +
  `commit(html)` 做 HTML 缓存，内容没变就完全不碰 DOM。
- **卡片白线的真因**：`border: 0.5px solid rgba(255,255,255,0.17)` 在半像素栅格上
  会渲染成一整条实心白线。改为无 border，用顶部渐变 sheen + 外层淡投影，
  加 `::before` 噪点（opacity .05 / mix-blend overlay）做磨砂颗粒，
  噪点必须 `z-index:0` 且 `.event-item > * { position:relative; z-index:1 }` 否则会盖住文字。
- **智能隐藏** `config.autoHide`：主进程 `setInterval` 150ms 轮询光标
  （`screen.getCursorScreenPoint()`），不依赖 DOM mouseenter/mouseleave —— 窗口只露 6px 时 DOM 事件不可靠。
  停靠判定 `b.y <= workArea.y + 8`；收起时 `y = workArea.y - height + 6`；展开回到 `smartDockY`。
  动作用 `setInterval` 分 10 步 setPosition 做 easeOutCubic（Windows 上 setBounds 的 animate 对透明窗无效）。
  踩过的坑：设置窗口开着时不要收起；刚显示 2.5s 内不要收起；F10 在收起态应是"拉回"而不是"隐藏"。

### 第四轮：统一材质 / 滚动 / 真隐藏 / 同步诊断
- **日程条不再有自己的磨砂**：去掉卡片上的 `backdrop-filter`、噪点、高光渐变，
  改成和设置页 `.card` 一样只有 `--card-fill` 半透明底 + 0.5px 发丝边（alpha 0.08），
  磨砂感统一来自 `#frost` 那一层。设置里也删掉了「日程条磨砂」滑块，只剩「背景」。
- **列表可滚动**：`.content` 改 `overflow-y:auto` + `scrollbar-width:none` +
  `::-webkit-scrollbar{display:none}`，并**渲染全部事件**（不再按可视高度裁剪）。
  这一步顺带把 F10 闪烁的根因彻底移除：不再有 getMaxRows / ResizeObserver 重排。
- **真隐藏**：不再 `win.hide()/show()`，改为 `body.slot-hidden { opacity: 0 }` +
  `win.setIgnoreMouseEvents(true)`。主进程 150ms 轮询 `getCursorScreenPoint()` 判断光标是否在窗口矩形内：
  进入 → 恢复；离开 260ms → 完全透明。悬停唤出必须 `focus:false`，否则会抢走别的程序的焦点。
  `wasInside` 用于避免"任务栏唤醒后被立刻隐藏"。
- **F10 不再闪**：因为根本不做 hide/show，也不重排 DOM，只切 opacity。
- **同步诊断**：`fetchICS` 系列改为返回 `{ok, events|error}`，新增 `diagnoseFetchError()`
  把 axios 错误翻译成「标题+技术详情+建议」，并检测"返回 HTML 登录页"（以前被当成无日程吞掉）。
  `linkErrors` 从 string 改为对象 `{name,url,title,detail,hint,count,at}`；
  连续失败 ≥2 次 + 30 分钟冷却 → 弹 `error-report.html`（新窗口，可复制 URL、重新同步、跳设置）。
- 设置页「日历源」加了刷新按钮（带 busy 态 + 8s 兜底）和失败提示条。

  另外 `get-calendar-data` 原来用 `cachedEvents.length === 0` 判断要不要拉数据 ——
  当天无日程时列表本来就空，于是每次渲染都发请求，这才是"一直在刷"的真凶。
  改成 `!hasFetchedOnce` 门闩（updateCache 的 finally 里置 true）。
- **日历滚不动的原因**：`.content` 是 `-webkit-app-region: drag`，

### 第六轮：iCloud 订阅超时 / 详情页空白 / 详情页材质
- **超时的两个真因**（不是"网络慢"）：
  1. Node 的 `https` **不读系统代理、不用系统证书库** —— 挂代理时浏览器能打开、程序一直 timeout。
     改用 `net.request`（Electron 自带 Chromium 网络栈）作为首选通道：走系统代理、系统证书、
     Happy Eyeballs（IPv6 不通自动回落 IPv4）、自动解压。失败再回退 Node axios。
  2. Node httpsAgent 加 `family: 4` 强制 IPv4 + keepAlive，并加 25s 超时 + 一次重试。
  另外把多个日历的拉取改为 `Promise.all` 并行（总耗时取最慢那个，不再累加）。
- **详情页显示"没问题"**：`render()` 里 `filter(e => e.count >= 2)` 把首次失败全过滤了。
  ≥2 只该用于"自动弹窗"，手动查看必须显示全部失败项。
- **详情页材质**：tint 从 0.78 调回 0.42、去掉写死的 blur(20px)，改成和主面板同一个
  `--frost-bg` 变量（跟设置里的"背景磨砂"联动），并监听 theme/frost/bg-image 变更。
- 详情窗也改成 `show:false` + 页面渲染完发 `report-ready` 再显示（1.2s 兜底），
  避免先闪一帧空状态。
